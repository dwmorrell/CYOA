# Accessibility review, 2026-10-20

**Method:** reading source only. No browser, device, screen reader, axe/Lighthouse run or build was available. **Every finding is `code-review`.** Nothing is `verified`. Contrast ratios are hand-calculated from CSS hex values and are approximate; re-measure with a tool before treating a number as final.

**Inputs read:** `index.html`, `src/main.ts`, `src/ui/{dom,prefs,reader,parent,catalog}.ts`, `src/styles.css`, `vite.config.ts`, `docs/UI_SPEC.md`, `docs/ACCESSIBILITY_AND_COMPATIBILITY.md`. `dist/` does not exist, so no built output was inspected.

## No known issue from reading (still untested)

- Real `button`, `fieldset/legend`, `label` and `h1` use in `reader.ts`, `prefs.ts`, `parentGate()`.
- Locked choice uses `aria-disabled` plus `aria-describedby` and stays focusable.
- `prefers-reduced-motion` removes the only transition (`.para` opacity).
- 3px focus ring with offset; `--focus` looks adequate against each theme (not measured).
- The viewport meta does not block zoom.

## Not covered

TalkBack and ChromeVox behaviour, real focus order, measured contrast, axe/Lighthouse, 320 px reflow, and `dist/` output.

## Re-review of fixes

**Scope and method:** `workflow/work-items.json` item WI-12 (status `ready-for-review`) lists 20 findings: 14 marked fixed and 6 marked open. I read the current `src/main.ts`, `src/ui/{dom,prefs,reader,parent,catalog}.ts`, `src/styles.css` and `index.html` and checked each claim against the code. I did not run the app, the tests, `npm run build`, a screen reader or a contrast tool. **Every verdict below is `code-review`.** Contrast ratios are hand-calculated from the CSS hex values and are approximate. A "fixed" verdict means the code now does what the finding asked for. It does not mean the behaviour works on a device. WI-12 also requires a TalkBack and ChromeVox check, which has not happened, so that acceptance criterion is still unmet.
